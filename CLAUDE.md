# Offer Studio — notas do projeto

App local (Mac, usuário único) para clonar, editar e exportar páginas de oferta. Plano e fases: docs/PLANO.md. Toda a interface e as mensagens de erro são em **português do Brasil**.

**Regra do usuário: toda a comunicação com ele é em português do Brasil, sempre** — respostas, mensagens curtas entre comandos, avisos de andamento, perguntas, descrições de comandos e mensagens de commit. Nunca alternar com inglês.

## Comandos
- `npm run dev` / `npm start` — sobem Postgres embutido + painel + worker (scripts/run.ts). `OS_DB_NAME` e `PORT` trocam banco/porta.
- `npm test` (Vitest, banco `offerstudio_test`), `npm run e2e` (Playwright, banco `offerstudio_e2e_auto`, porta 3200), `npm run verify` (tudo).
- `npx tsx scripts/with-db.ts [--db nome] -- <comando>` roda algo com o Postgres ligado (ex.: `prisma migrate dev`).
- Postgres embutido é COMPARTILHADO (app, testes, E2E, scripts) no mesmo cluster `data/postgres`: `startPostgres` liga destacado (pg_ctl) e registra quem usa em `data/postgres-users`; `handle.stop()` só desliga quando é o último. Nunca pare o servidor de outro jeito (pg_ctl stop, kill) — derruba o app aberto.
- Nunca use o banco `offerstudio` (dados reais do usuário) em testes.
- `embedded-postgres` só via `loadEmbeddedPostgres()` (scripts/lib/postgres.ts): importado direto, o `async-exit-hook` dele mata o processo no Ctrl+C antes de sair da lista de usuários do banco.
- App de rascunho (verificação manual): `PORT=<p> OS_DB_NAME=offerstudio_<algo> DATA_DIR=<pasta temporária> OS_OPEN_BROWSER=0 npm start`; desligue com SIGINT no grupo de processos (como o Ctrl+C), nunca matando o Postgres.
- `npm run redefinir-senha` (scripts/reset-password.ts) troca a senha da conta única.

## Convenções
- Server actions: `protectedAction(schemaZod, handler)` em src/server/actions — exige login, valida com zod (mensagens pt-BR) e traduz erros via `toUserMessage` (src/lib/errors.ts). No cliente, use `useAction()` (toasts automáticos).
- Regras de negócio em src/server/services (testáveis sem Next); consultas de tela em src/server/queries.ts.
- Erros para o usuário: lance `UserError("mensagem em pt-BR", "campo")`.
- Links entre páginas do funil são gravados como `os-page:<pageId>` (src/lib/internal-links.ts).
- Arquivos: src/lib/storage.ts (disco local, endereçado por hash). Arquivos de páginas clonadas são referenciados como `/os-assets/<sha256>.<ext>`.
- Clonador: src/worker/clone (job.ts orquestra; capture.ts = Playwright; build.ts = saídas EDITABLE/PRESERVE_JS). O que os scripts faziam e o modo Editável precisa sem eles vai em editable-compat.ts (ex.: players montados por script como o Presto Player viram o vídeo comum do editor: `convertScriptPlayers`). Salvar em "Preservar JS" guarda também a cópia editável em `PageDocument.editableHtml`; "Converter para editável" troca por ela (`convertToEditable`, src/server/services/documents.ts). Versões do Histórico gravam o modo (`preserve` no snapshot) e restaurar volta o modo; quem copia/reescreve documentos (duplicar, versão A/B, localizar e substituir) leva `editableHtml` junto. Testes de ponta a ponta: tests/unit/clone-job.test.ts com os sites offline de tests/fixtures (`OS_CLONE_HOST_MAP=*.fixture.test=127.0.0.1`).
- Editor visual: src/editor (GrapesJS 0.23.6, UI própria em editor-app.tsx; config em grapes/setup.ts; blocos em blocks/, widgets em widgets/, modelos em templates/). HTML salvo ↔ editor por src/lib/editor-html.ts (scripts viram <os-script>, on* viram data-os-on-*, CSS original numa folha base em @layer os-original). Nada executa no canvas; comportamento das páginas fica em src/runtime (widgets via data-os-widget), injetado por src/lib/page-render.ts. Timers de módulos do editor: use editorTimeout (grapes/lifecycle.ts). HTML da página entra no editor por `importPageHtml` (grapes/setup.ts) e projetos salvos passam por `fixPageRoots`: a raiz da página é sempre "wrapper" (um <body> só com quebra de linha era detectado como "text" e o projeto salvo não abria mais).
- Botões ligados a links da oferta: data-os-link="<chave>" (src/lib/offer-links.ts).
- Quiz (data-os-widget="quiz"): CSS e definições em src/editor/widgets/quiz-content.ts (usadas pelo bloco, pelo modelo "Quiz" e pelos "＋ Adicionar…"), tipos/Configurações em widgets/quiz.ts, página em src/runtime/widgets/quiz.ts. Etapas `section[data-os-qz-step=question|info|loading|final]` dentro de `[data-os-qz-steps]`; opções `button[data-os-qz-option]`; botão final `a.os-btn[data-os-qz-go]` (destino como o de qualquer botão). Visual por classes os-qz-* com cores em variáveis no quiz (--os-qz-main/-sel/-cta). No CSS que passa pelo GrapesJS, atalho com var() (border, background, outline…) se perde: use propriedades simples (background-color, border-top-color…), e só um :hover por @media. Selo "Etapa N de M" só no elemento desenhado (data-os-qz-badge, nunca no modelo). Sem JS só a 1ª etapa aparece (`.os-quiz:not(.os-qz-on):not([data-gjs-type])`). Eventos: o quiz dispara "os:quiz" e src/runtime/tracking/quiz.ts manda QuizPergunta<N>/QuizConcluido (GA4: quiz_pergunta_<N>/quiz_concluido) pelo mesmo `fire` (consentimento), sem texto das respostas e sem eventos.php (2º quiz da página leva quiz_numero). A etapa final é `removable:false` (não crie "＋ Adicionar final"). Rolagem automática da página (ex.: quiz voltando ao topo): `markAutoScroll()` (src/runtime/widgets/util.ts), senão o popup de saída do celular abre. Texto de `<button>` editável sempre num `<span>` dentro dele (Espaço num button contenteditable vira clique no Chrome/Firefox). Campos de cor das Configurações: tipo `os-color` (src/editor/widgets/traits.ts), não o `color` do GrapesJS (regrava ao trocar de elemento).
- Roleta de desconto (data-os-widget="wheel"): fatias em `data-os-slices` (JSON; formato, sorteio, parada e desenho em src/lib/wheel.ts — sem dependências, entra no script das páginas: nada de desestruturação, o alvo é Safari 13). CSS/definição em src/editor/widgets/wheel-content.ts (bloco e modelo "Roleta", tipo OTHER), tipos/Configurações em widgets/wheel.ts (campo próprio `os-slices`, atualizado no lugar quando só um valor muda — refazer os campos tira o foco do painel e o Backspace apagaria a roleta; a roda SVG, o texto do prêmio e o cupom de exemplo são gerados em `getInnerHTML`, nunca guardados como elementos), página em src/runtime/widgets/wheel.ts. Destino de botão de saída (quiz e roleta): `destination()` em src/editor/widgets/destination.ts. "＋ Criar link da oferta…" fora de uma lista de link: `requestNewLink(editor, { component, kind, name, bind })` (src/editor/grapes/new-link.ts). Prêmio levado às outras páginas: src/runtime/widgets/prize.ts — o render embute o mapa `#os-premios` (prizeId = link + hash do texto → endereço, src/lib/wheel-prizes.ts, montado de todas as roletas da oferta: `offerWheelRender` na prévia, `wheelRenderData` no ZIP) e marca `data-os-link-kind="checkout"`; a página só aceita prêmios do mapa (URL `os_premio=<id>.<validade>` e localStorage `os_premio:<código da oferta>` nunca dão endereço); a memória é separada por oferta (`data-os-oferta` = `offerScope(offerId)`, posto pelo render — passe o `offerId` ao `wheelRenderData`). Os botões de checkout trocam também na página da roleta (e o "Resgatar" ligado a um checkout vai ao checkout do prêmio). O "Resgatar" parte de `data-os-wh-href` (destino antes do repasse) e chama `__osTracking.relink()` depois de mudar. Visibilidade `data-os-premio="ganhou|nao"` (CSS no <head> pelo render; classe `os-premio-on` no <html>). Eventos "os:wheel" → RoletaGirou/RoletaResgatou (GA4 roleta_girou/roleta_resgatou), src/runtime/tracking/wheel.ts. Avisos: `wheelPrizesWarning`/`deadWheelButtonsWarning` (ZIP) e passo "roleta" do "Próximos passos" (alvo `{ editor: documentId }`).
- Funil em 1 clique "Quiz → Roleta": `createQuizWheelFunnel` (src/server/services/funnel.ts) numa transação; serviços que entram numa operação maior recebem `db: Db = prisma` (src/lib/db.ts, `atomically` quando o serviço tem a própria transação). Janela em src/components/offers/funnel-dialog.tsx, regras em src/lib/funnel.ts.
- Rastreadores escondidos: código codificado (atob + XOR, o código novo da UTMify) e scripts em `src="data:…"` (JS adiado por WP Rocket/LiteSpeed) são lidos por src/detection/encoded-loader.ts (`withDecodedLoaders`, `readableCode`, `dataUriScript`). Quem analisa scripts procurando rastreador ou ID (clonagem, campo de ID, código livre) passa o texto por eles.
- Prévia: src/preview/server.ts em <token>.localhost:<PORT+1>, tokens em src/lib/preview.ts.
- Componentes base em src/components/ui seguem o shadcn/ui (o registro do shadcn é inacessível nesta rede: escreva à mão).
- Nada de botão sem ação: o que é de fase futura fica oculto até existir.
- Formulários do painel: `useDraft` + `SaveBar` (src/components/offers/tracking/form-kit.tsx) — "Alterações não salvas · Descartar · Salvar". O SaveBar chama `useUnsavedChanges` (src/hooks/use-unsaved-changes.ts): a aba ganha um ponto e sair por um link pergunta antes (UnsavedChangesGuard montado na tela). Abas com formulários usam `<TabsContent keepMounted>` (o não salvo continua lá na volta).
- Endereços de links da oferta: `linkUrlProblem`/`linkUrlHint` (src/lib/link-url.ts), na ação e na tela. Tamanhos de arquivo: `formatBytes` (src/lib/format.ts).
- Tela da oferta: abas na URL (`?aba=links|rastreamento|configuracoes|detalhes`, `&secao=` nos pixels: src/components/offers/offer-tabs.tsx). "Próximos passos": `computeReadiness` (src/lib/readiness.ts + src/server/services/readiness.ts). Avisos do ZIP: src/lib/export/warnings.ts (com consertos em src/components/offers/export/warning-fixes.tsx).
- Pagamento na página (gateway Kyvo; outros depois): link da oferta com `target=PAYMENT` + `PaymentProduct` (valor em centavos, moeda MXN/EUR/USD, métodos SPEI/CARD/BIZUM/MB_WAY, idioma da janela, página de obrigado, link de acesso — este NUNCA vai para o HTML). Regras puras em src/lib/payments/rules.ts (moeda × método, faixas, `parseAmount`, `paymentProductProblems`, usadas na tela e no serviço); contrato do endpoint da página (prévia `/__os/pagamento`, ZIP `pagamento.php`), do JSON `#os-pagamento` e do botão `data-os-pay` num lugar só: src/lib/payments/contract.ts; pedido `os_<código do produto>_<20>` (src/lib/payments/orders.ts, = externalOrderId = Idempotency-Key = eventID do Purchase e transaction_id do GA4/Google Ads); o código é `orderProductCode(chave, linkId)` — chave do link cortada + resumo do linkId: a chave do link se repete entre ofertas e a chave da Kyvo é uma só, então nunca identifique o produto só pela chave do link. Chave de link de pagamento até 80 (`PRODUCT_KEY_RE`, a mesma do pagamento.php e do prize.ts; `linkKey` nunca passa de SLUG_MAX). `parseAmount` recusa "49,900" (vírgula com 3 algarismos: engano, não milhar). Camada genérica `PaymentGatewayAdapter` (src/lib/payments/gateway.ts), adaptador em src/server/services/payments/kyvo.ts (endereço da API só troca por `OS_KYVO_API_BASE` apontando para 127.0.0.1/localhost — testes com o servidor falso tests/unit/kyvo-fake.ts; nunca chame a Kyvo de verdade nos testes). Chave da API em `PaymentGateway.apiKeyEnc` (crypto.ts, como os tokens; coluna listada em `ENCRYPTED_COLUMNS` do backup) — a tela recebe só `keyHint`. Estado da chave: `gatewayKeyState` (src/lib/payments/checks.ts) — `rejected`/`no_scope` vêm do último "Testar conexão" (`checkStatus`, zerado ao trocar a chave) e contam como problema no "Próximos passos", no ZIP (a chave sai vazia no config.php) e no formulário do produto. Quem monta links para o render usa `loadRenderLinks`/`renderLinks` (src/lib/payments/links.ts: `pay` sem endereço) e `linkHasDestination`; a prévia é SEMPRE simulação (src/server/services/payments/simulation.ts). Tela: Configurações → Pagamentos (payments-card.tsx) e o formulário do produto na aba de links (payment-product-form.tsx). Prêmio da roleta pode ser link de pagamento (`p` no mapa de prêmios; `swapCheckouts` troca `data-os-pay`).
