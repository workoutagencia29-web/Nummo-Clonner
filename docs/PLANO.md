# Offer Studio — plano aprovado

Aprovado em 28/09/2026, com os ajustes pedidos depois da primeira versão:

- **Sem domínios, subdomínios nem hospedagem.** O Offer Studio roda no Mac do usuário (atalho de duplo clique) e a saída de cada oferta é um **ZIP** pronto para subir em qualquer hospedagem.
- **Um usuário só.** Sem gestão de equipe, papéis ou log de atividades; login simples.
- **Editor com prévia ao vivo**: edição direto na página (o que se vê é o que sai) + modo Prévia com os scripts rodando, atualizado a cada alteração.
- **Teste A/B** = versões da página exportadas em pastas separadas (`oferta-a/`, `oferta-b/`…) + `index.html` divisor opcional por percentual.

## Consequências (sem servidor próprio)

1. Métricas de visitas/cliques no painel foram removidas: ficam no UTMify, Meta e GA4.
2. API de Conversões (Meta) e Events API (TikTok): opcional via `eventos.php` incluído no ZIP, para hospedagens com PHP (Hostinger, HostGator, cPanel). Desligado por padrão.
3. Formulário de captura envia para um webhook do usuário e/ou redireciona.
4. Consentimento LGPD: pixels só depois de aceitar (padrão), ajustável por oferta.

## Fase 4 — o que foi entregue

- **Por oferta**: pixels (tabela `PixelConfig`), regras de evento (`EventRule`) e configurações (`Offer.tracking`), com contrato em `src/lib/tracking/schema.ts`. Duplicar a oferta copia tudo (regras remapeadas para as páginas novas).
- **Pixels**: Meta, TikTok, Kwai, GA4, Google Ads (rótulo de conversão por evento) e UTMify (pixel + script de UTMs). O ID é extraído do código colado. O token da API de Conversões/Events API fica em AES-256-GCM (`APP_ENCRYPTION_KEY`) e só sai do servidor para o `eventos.php` da Fase 5.
- **Script das páginas** (`src/runtime/tracking`, ~24 KB, ~10,5 KB com gzip): consentimento LGPD (OPT_IN padrão, NOTICE, OFF) com Google Consent Mode v2, pixels com o mesmo `eventID` em todas as plataformas, regras (abrir a página, tempo com a aba visível, rolagem — numa página curta vale ao carregar, a menos que ela ainda vá crescer: VSL com atraso ou imagem "lazy" sem altura por carregar; escondida, quebrada ou com altura reservada não segura —, clique em checkout/link/seletor, formulário e `data-os-event` do editor — num botão de enviar, conta no envio válido ou, se a página tratar o clique (fetch, `return false`), no clique), repasse de UTMs e IDs de clique (último clique vale inteiro, persistido por N dias; formulários GET recebem campos escondidos; no "Pedir permissão", ver Decisões), banner do "Pedir permissão" quando a página tem pixels/código de marketing ou quando a chegada traz IDs de clique ou UTMs para guardar (mesmo sem pixels; com um formulário de captura ligado a um webhook, os IDs de clique contam mesmo com o repasse desligado), botão flutuante "Cookies" só no "Pedir permissão" (e para quem recusou) e só nas páginas sem o link "Preferências de cookies" (sobe acima de barras fixas no rodapé, também das que aparecem depois por transição, timer ou classe), um "Recusar" guardado continua valendo se a oferta passar para "Só avisar" (sem pixels nem `_fbc`/`_fbp`/IDs de clique; o botão "Cookies" deixa aceitar; o código livre do "Só avisar" roda no lugar, para todos), revogação que recarrega a página e códigos livres que esperam o "Aceitar" (categoria por oferta e por página; em espera num bloco inerte `<script type="application/json" data-os-consent data-os-block>` (nenhum navegador pré-carrega nada de dentro dele — o `<template>` antigo deixava o Firefox baixar imagens antes do "Aceitar"; o formato antigo ainda é ativado), posto no HTML pelas posições do parser — nunca dentro de um comentário —, com DOMContentLoaded/load e o onload/onerror do próprio script entregues ao ativar; `<script nomodule>` não segura os seguintes e nenhum script externo segura por mais de 10 s). Clique ou envio de formulário que troca de página com o script de um pixel ainda carregando espera até 0,8 s (links e formulários de checkout: decidido na bolha da janela ou logo depois de um script da página que pare a propagação; se a página tratar o evento, mesmo depois, vale o dela; o formulário é reenviado sem repetir os ouvintes da página; botões `data-os-href` e formulário de captura: `window.__osTracking.pending/settled` no `os-runtime`, com o webhook ao mesmo tempo); clique duplo não fura a espera, nem um link clicado durante a espera de um botão `data-os-href` (`window.__osTracking.leaving`, a mesma marcação nos dois scripts). No Safari < 15.4 (sem `SubmitEvent.submitter`), o formulário segurado é reenviado com o botão do último clique (nome/valor, `formaction`/`formmethod`). Alvo: Safari 13 (nada de `Object.hasOwn`, `.at()`, `replaceAll`… — um teste confere o script compilado).
- **Dados pessoais**: "Levar nome e e-mail" do formulário de captura só põe nome/e-mail/telefone na URL quando o destino é outro site; para uma página do funil, eles vão pela sessão (`os_lead`) e só entram nos links de checkout de lá (os pixels mandam o endereço da página às plataformas). O `event_source_url` do `eventos.php` sai sem `name`/`email`/`phone`/`cpf`…
- **Montagem** (`renderPageHtml`): configuração pública + script no começo do `<head>` (logo depois do charset/viewport), códigos livres com a categoria aplicada (código de página sem categoria escolhida que tem pixel/tag vale como "Marketing": `resolveCodeCategoryFull` em `src/lib/tracking/code-trackers-server.ts` — assinaturas do clonador, RD Station/HubSpot/Mouseflow/Criteo… e, no servidor, a base third-party-web; na página publicada, só o "Pedir permissão" põe o código em espera). Pixels mantidos na revisão da clonagem vão para os códigos da página (categoria "Marketing"), não para o HTML; o editor não aplica HTML de elemento com pixel novo, e o painel avisa das páginas cujo HTML ainda tem pixel e o `os-runtime` por último. Os marcadores da empresa (`{{EMPRESA}}`…, com "CPF"/"CNPJ" pelo número) e o SEO (`applySeo`: título, descrição, favicon, imagem de compartilhamento, noindex e `<html lang>`) valem na prévia. "Idioma das páginas" vem vazio ("Igual à página"): o `<html lang>` de cada página fica como está (página clonada em inglês continua "en"); o diálogo "SEO da página" mostra o título/descrição que a página já tem.
- **Prévia**: modo `preview` (pixels desligados); com `?os_teste=` de uma sessão, modo `test` (redireciona para o mesmo endereço sem o token, pixels de verdade, cookie para seguir pelo funil, `POST /__os/pixel-test` com limite de tamanho, ritmo e 2000 passos por sessão).
- **Painel**: aba "Pixels e rastreamento" (Pixels, Eventos, Privacidade, UTMs, Código livre), aba "Empresa e SEO", "SEO da página" na lista de páginas e tela **Testar pixels** (ao vivo, com lista de conferência por plataforma e dicas em português).
- **Editor**: "Evento ao clicar" em botões e links; link "Preferências de cookies" no rodapé, nos modelos e como bloco próprio.
- **Decisões**: o Kwai recebe os nomes do pixel web (`contentView`, `initiatedCheckout`, `formSubmit`…; os `EVENT_*` são da API de servidor). A UTMify dispara os próprios eventos (o painel avisa para não repetir o pixel da Meta). No modo "Só avisar", o texto padrão do aviso não fala em recusar nem diz que continuar navegando é concordar (guia da ANPD). A UTMify aceita um pixel por oferta. Telefone e endereço da empresa são opcionais: vazios, o trecho sai da política e dos termos (`<span data-os-company>`).
- **Decisão (repasse no "Pedir permissão", a confirmar com o usuário)**: antes do "Aceitar", nada fica guardado no aparelho (nem as UTMs), os IDs de clique de anúncio (fbclid, gclid…) seguem só no endereço dos links entre as páginas do funil (quem aceita numa página seguinte não perde a atribuição) e ficam fora do checkout e do webhook do formulário de captura; as UTMs da visita atual vão para o checkout. "Aceitar" guarda tudo e completa o checkout; "Recusar" apaga o que estava guardado e tira os IDs de clique de todos os links. Efeito: quem ignora o aviso e volta depois direto (sem UTMs) chega ao checkout sem a origem. A alternativa (guardar só as UTMs antes da escolha e mandar ao checkout os IDs de clique da URL atual) é uma troca de poucas linhas em `src/runtime/tracking/index.ts`; os textos do painel ("UTMs e checkout" e "Privacidade") descrevem a regra atual.
- **Para a Fase 5 (ZIP)**: `loadTracking({ mode: "live", pageHref, serverEndpoint: "eventos.php" })` + `inlineTrackingScriptTag()`; tokens por `readPixelTokenForServerFile`. O `eventos.php` recebe JSON como `text/plain` (sendBeacon): `{event, event_name:{META?,TIKTOK?}, event_id, event_time, event_source_url, value?, currency?, fbp, fbc, ttp, ttclid}`. O PageView do TikTok não tem `event_id` no navegador, então o script não o manda ao `eventos.php` (só a Meta recebe o PageView pelo servidor). SEO: `renderPageHtml({ seo: seoRenderFrom(effectiveSeo(...), language, prefixo dos arquivos) })`; `language` pode ser `""` (igual à página): o divisor A/B precisa de um valor (ex.: `settings.language || "pt-BR"`).

## Fase 5 — o que foi entregue

- **Teste A/B** (menu **⋯ → Teste A/B** da página e selo "N versões A/B"): até 5 versões (A–E) por página; nova versão como cópia de qualquer versão (todos os documentos, inclusive o celular separado e o `assetMap` do "Preservar JS"), de um modelo ou em branco, com nome opcional (entra na divisão por igual com as versões ativas; as pausadas continuam em 0%: `weightsAfterCreate`); divisão do tráfego em inteiros que sempre somam 100 (editar uma ajusta as outras; "Dividir por igual", "Desfazer"; 0% = pausada; salvar confere a divisão de onde a pessoa partiu, então outra aba nunca é sobrescrita sem aviso); controle (exatamente um), renomear, excluir (o percentual vai para as outras na proporção). Tudo em transação com a página travada (`SELECT … FOR UPDATE`), então cliques simultâneos nunca quebram as regras; uma ação que esbarra numa mudança de outra aba recarrega a lista e avisa (`isStaleVariantsError`). No editor, seletor "Versão A / B / …" (salva antes de trocar e mantém o aparelho). Duplicar página/oferta copia as versões. Código: `src/server/services/variants.ts`, `src/components/offers/variants/`.
- **Baixar ZIP** (botão na oferta e item no menu do card, `?baixar=1`): prévia do que vai no ZIP (`exportPlanAction`), opções (divisor A/B, `eventos.php`, HTML otimizado), andamento com etapas em português (fila no worker, `GET /api/exports/<id>` a cada segundo), download automático, histórico com os 5 últimos ZIPs por oferta (limpeza no worker) e guia "Como subir na hospedagem" (Hostinger e cPanel com os nomes reais dos botões; no Safari, que descompacta o ZIP e manda o .zip para a Lixeira, um aviso no "ZIP pronto" — o mesmo no guia, no LEIA-ME e no README). Duplo clique devolve o mesmo pedido; no máximo 3 na fila por oferta; worker fechado no meio vira "Falhou" com mensagem clara.
- **Montagem** (`src/server/services/export/build.ts`, formato em `src/lib/export/options.ts`): cada arquivo passa pelo `renderPageHtml` da prévia no modo `live` (pixels de verdade, `eventos.php` com caminho relativo), SEO/empresa, scripts do Offer Studio como `assets/os-runtime-<hash>.js` e `assets/os-tracking-<hash>.js`, links do funil relativos à pasta ("../upsell/"), `/os-assets/` → `assets/` (também dentro dos CSS, recursivamente), canonical nas cópias (sem `noindex`: é o que o Google pede para testes A/B), obrigado/upsell/downsell com `noindex` quando a pessoa não escolheu nada no SEO, metas de verificação de domínio dos códigos livres sempre no `<head>` de verdade (fora do bloco que espera o "Aceitar"), og:image/twitter:image com endereço completo quando há "Onde está no ar" (senão, aviso), script de chegada (barra no fim, celular → `celular/`, versão A/B vista, `file://`; o caminho é normalizado, nunca redireciona para outro site). "Preservar JS" nos caminhos originais e copiado para as pastas das versões/do funil quando a página sai da pasta original; nunca arquivos que a hospedagem executaria (`isServerSidePath`: `.php` em qualquer extensão, `.htaccess`, `.user.ini`, `web.config`, ocultos, `cgi-bin/`) nem caminhos que colidem (arquivo × pasta, maiúsculas: `ZipPathSet`; `writeZip` recusa como última defesa). ZIP determinístico (yazl, entradas ordenadas; data = a maior entre a última alteração da oferta e o pedido do ZIP), gravado em temporário e renomeado.
- **Divisor** (`src/lib/export/splitter.ts`): ES5, sorteio pelo peso, escolha guardada por até 30 dias (localStorage e cookie; no iPhone/Safari o navegador apaga em ~7 dias), só para a mesma versão (pasta + identidade: letra recriada sorteia de novo); as páginas das versões gravam a mesma escolha (quem chega direto em `oferta-b/` continua nela). Mantém query string e `#hash`, `location.replace` (a origem de outro site — endereço http(s) ou app Android, como o app do Google e o Gmail — fica em `sessionStorage` "os_ref" com a hora, e o script de chegada da página que fica a devolve ao `document.referrer` antes do rastreamento se tiver menos de 1 minuto — `RESTORE_REF_JS`: GA4, Meta, TikTok e UTMify veem o Instagram/Google, não o divisor; uma chave que sobrou na aba não vale para uma visita depois), celular direto para `celular/` da versão, `<noscript>` para a versão de controle, funciona na raiz, em subpasta, sem a barra no fim e em `file://`. O `<head>` do divisor copia da versão de controle o título, as metas de verificação, descrição, og:* (menos og:url), twitter:* e ícones — nunca scripts/pixels. O cookie `os_ab_<chave>` é **funcional** (só lembra a pasta da versão, não identifica o visitante): grava antes do "Aceitar".
- **eventos.php** (`src/lib/export/php.ts`, PHP 7.4+): recebe o `sendBeacon` do script das páginas, exige Origin/Referer do próprio site (não é autenticação: o endereço é público como o pixel), limita o tamanho e os eventos por IP, responde 204 antes de repassar (cURL ou `allow_url_fopen`) à API de Conversões e à Events API. IP = o da conexão (`REMOTE_ADDR`); `CF-Connecting-IP` só com a conexão vindo das faixas da Cloudflare, `X-Forwarded-For` só com `'trust_proxy' => true`. Tokens em `eventos-dados/config.php` (404 se aberto direto; `eventos-dados/.htaccess` bloqueia a pasta no Apache/LiteSpeed): o ZIP nunca traz `.htaccess` na raiz (substituiria o da hospedagem). O `LEIA-ME.txt` explica a hospedagem, o teste A/B (e como comparar as versões), como testar o `eventos.php` e pede para apagar o ZIP e o LEIA-ME da hospedagem.
- **Verificado de ponta a ponta** (smoke fora dos testes, banco próprio): oferta de modelos com A/B 70/30, upsell, obrigado, política e termos, pixel da Meta com token → ZIP pelo laço do worker → `unzip` → servido na raiz e em subpasta → Chromium: todas as páginas sem 404, funil entre pastas com UTMs, divisor 200 visitas dentro de 70% ± 8 e fiel ao sorteio, escolha lembrada, banner LGPD, pixel e `eventos.php` com o mesmo `event_id`; e o `eventos.php` no PHP 7.4 (WebAssembly) montando o pedido da API de Conversões com o token exato.

### Notas de manutenção (vindas da Fase 5)

- A lista de navegadores de celular do ZIP (`MOBILE_UA_SOURCE` em `src/lib/export/head.ts`) é cópia da de `isMobileUserAgent` (`src/lib/page-render.ts`): mudou uma, mude a outra.
- A tela do ZIP esconde o aviso do plano que contém "eventos.php" e "PHP" (já aparece na opção): mantenha as duas palavras se reescrever esse aviso.
- "Preservar JS" vale por documento no editor (documento com `assetMap`); uma versão A/B criada de um modelo numa página "Preservar JS" abre direto no editor. No ZIP, o modo continua por página (só evita otimizar o HTML).
- "Converter para editável" (página "Preservar JS"): a página passa a ser a cópia editável da mesma clonagem, guardada ao salvar (`PageDocument.editableHtml`) — o editor não roda scripts, e o HTML original sem eles aparecia em branco (Elementor, WP Rocket, players). Vale para a versão A/B inteira (computador e celular); o Histórico ganha "Original com scripts (antes de converter)" (restaurar volta os arquivos originais e o modo) e "Versão original (editável)". A página só vira "Editável" quando nenhum documento dela tem mais `assetMap`. Páginas salvas antes da cópia editável abrem o HTML original, com aviso.
- Com o divisor ligado, o `index.html` da página inicial é o divisor (`noindex`) e a versão de controle tem o canonical: para SEO orgânico, desligue o divisor ou mande o tráfego direto para a pasta da versão.
- Teste A/B medido (Fase 6, pendências (1)–(5) resolvidas): cada versão manda `os_versao` (a letra) em todo evento — Meta `custom_data`, GA4 (parâmetro + propriedade de usuário), TikTok/Kwai `properties` (os PageView deles não aceitam parâmetros), `eventos.php` — e marca o checkout com `versao-<letra>` só quando o parâmetro não existe: `src` na Hotmart/Kiwify/Eduzz (`sck`/`xcod` nunca), `utm_content` nas outras. **Decisão a confirmar com o usuário**: um `utm_content` trazido pelo visitante (anúncio, "nome|ID", lido pela UTMify) nunca é alterado (não vira `…|versao-b`), então nessas plataformas o tráfego pago com UTMs chega ao checkout sem a versão (o LEIA-ME e o "Teste A/B" dizem para usar outro link de checkout por versão); mudar é uma troca pequena em `markVersion` (`src/runtime/tracking/forwarding.ts`). A prévia/"Testar pixels" de uma versão só leva a versão quando `src/preview/server.ts` passa `variantId` ao `loadTracking`. Metas de verificação de domínio ficam fora do bloco em espera também na prévia (`gateCode` → `src/lib/tracking/domain-verification.ts`); a política de privacidade (modelo) cita `os_consent` e `os_ab_…`.
- O endereço da API de Conversões usa a versão da Graph API fixada em `META_EVENTS_URL` (`src/lib/export/php.ts`); revise quando a Meta encerrar essa versão.
- Sem `php` no Mac, os testes do `eventos.php` no PHP de verdade (`tests/unit/export-php.test.ts`) ficam pulados; a sintaxe é conferida pelo `php-parser`. Para rodá-los: PHP em WebAssembly (`@php-wasm/cli`) com `OS_PHP_BIN` (ver o cabeçalho do teste).

## Fase 6 — o que foi entregue

- **Backup** (`src/server/services/backup`, tela em Configurações → Backup, `src/app/(painel)/configuracoes/backup-card.tsx`):
  - **Arquivo**: ZIP com manifesto (formato, versão do app, migrations, contagem de linhas e SHA-256 de cada tabela e arquivo, impressão digital da chave), as tabelas em JSONL na ordem das dependências, os arquivos do storage usados (com índice) e a chave de criptografia. Gravado em temporário e renomeado, com conferência de espaço em disco. Os ZIPs do "Baixar ZIP" ficam de fora.
  - **Pasta**: Documentos › Offer Studio Backups (padrão), iCloud Drive (quando ligada) ou outra pasta validada. Fora do banco `offerstudio`, a pasta "de casa" é `<DATA_DIR>/backup-home` (`OS_BACKUP_HOME` troca): testes nunca gravam nos Documentos de quem usa o Mac.
  - **Agenda** (worker): automático todo dia (padrão 03:00) com o app aberto, mais um de recuperação quando o último automático tem mais de 24 h; guarda os N últimos automáticos (padrão 10) e só apaga automáticos desta instalação; manuais ficam. Tarefas interrompidas viram "Falhou".
  - **Restauração**: confere o arquivo inteiro antes (recusa versão mais nova, aceita as antigas), faz um backup de segurança ("Antes de restaurar"), copia só os arquivos que faltam (nunca sobrescreve), troca os dados numa transação só mantendo as configurações deste Mac (`AppSetting` locais), acerta as sequências, criptografa de novo os tokens dos pixels quando a chave é outra, encerra as sessões e pausa as outras filas enquanto roda. Limites de tempo: trava das tabelas (30 s no total, senão "ocupado"), comando (5 min), pausa dentro da transação (2 min), conexão (15 s), leitura do arquivo parada (2 min). Qualquer falha deixa os dados como estavam, com mensagem em pt-BR.
  - **Telas**: "Fazer backup agora", lista "Backups encontrados", "Restaurar" com "RESTAURAR" digitado e tela de andamento, "Restaurar de outro arquivo…", saúde do backup no cartão Sistema e, numa instalação nova, "Restaurar de um backup" na primeira tela.
- **Teste A/B medido**: `os_versao` em todos os eventos e marca `versao-<letra>` no checkout (ver as notas de manutenção e as decisões abaixo); "Testar pixels" com escolha da versão.
- **Polimento** (três rodadas de revisão com correções):

## Funil com quiz — correções da revisão da roleta (03/10/2026)

- **Campo "Fatias"**: mudar um valor (texto, chance, cor, cupom) atualiza a lista no lugar; só muda de forma (fatia nova, removida, de lugar, "Sem prêmio", aviso) refaz os campos, com o foco de volta no mesmo campo (ou no "＋ Adicionar fatia"). ## Limitações conhecidas

- Sites com anti-robô/cloaker são detectados e explicados, nunca contornados (alternativa: importar o HTML/ZIP salvo no navegador).
- Quizzes/SPAs que dependem do servidor do dono não ficam 100% independentes.
- Quiz: os eventos do quiz vão só pelo navegador (não pelo `eventos.php`); Kwai, Google Ads e UTMify não os recebem. O gesto de voltar do celular sai da página (o quiz não mexe no histórico).
- Funil em 1 clique: cria sempre o quiz e a roleta dos modelos (textos de exemplo para trocar no editor); não liga os botões de compra da página de vendas a um checkout (só avisa). O aviso do ZIP para prêmio com link sem endereço continua dizendo para abrir a roleta no editor (lá a fatia mostra "preencha em Links e checkouts").
- Roleta: o sorteio roda no navegador (quem sabe programar pode forçar um prêmio, como em qualquer roleta sem servidor); "uma vez por visitante" vale por aparelho/navegador (aba anônima gira de novo). Os eventos da roleta vão só pelo navegador. Excluir um link usado como prêmio deixa a fatia "sem link" (a confirmação e os avisos dizem isso). O ZIP não avisa quando nenhum botão de compra está ligado a um checkout (só o "Próximos passos").
- VSLs de terceiros (Panda/VTurb) podem bloquear o domínio: troque pelo seu vídeo.
- Detecção de checkout é heurística; há "marcar como checkout" manual.
- Upsells configurados dentro das plataformas não aparecem a partir da página de vendas.
- Clonar conteúdo de terceiros pode violar direitos autorais; a responsabilidade é do usuário.
- Sem servidor próprio, não há métricas no painel: visitas, cliques e vendas por versão ficam no UTMify, Meta e GA4 (por `os_versao`).
- O "Próximos passos" avisa dos links que ainda levam ao checkout da página clonada; a janela do ZIP avisa de botões sem link, mas não desses checkouts antigos (a regra está pronta em `computeReadiness` para ser reaproveitada em `src/server/services/export/plan.ts`). Links comuns com `href="#"` (sem link da oferta) também não geram aviso.
- O card da oferta não mostra um selo "botão sem link" (só o "Próximos passos" dentro da oferta).
- `/ofertas/<id inexistente>` e `/ofertas/<id>/testar-pixels` mostram a tela "não encontrada", mas respondem HTTP 200 (o `loading.tsx` começa a resposta antes); o editor responde 404.
- No editor, títulos (h1–h6) aparecem como "Texto" no nome do elemento.
- Ofertas criadas de modelos antes da Fase 6 não ganham a miniatura do modelo (só as novas).
- A janela de imagens do editor é a do GrapesJS (com foco, Esc e "Fechar" acessíveis), não um diálogo do painel.
- O contador regressivo de uma página clonada no modo Editável fica parado: a revisão avisa e oferece "Com scripts", mas não troca sozinha pelo bloco "Contador regressivo".
- O editor é para computador: abaixo de 900 px de largura ele avisa e oferece "Ver página" (o painel funciona no celular).
- Backups de uma versão mais nova do Offer Studio não restauram numa versão mais antiga.
- Sem `php` no Mac, os testes do `eventos.php` no PHP de verdade ficam pulados (a sintaxe é conferida; no PHP em WebAssembly, dois testes de comportamento de rede não se aplicam).
